# 席ごとのデモ画面の文言と構成（2026-09-06）

対象は `qomm_demo/static/`（`index.html` / `demo.js` / `demo.css`）と、
`qomm_demo/react-flow/` から生成する React Flow の束です。サーバー（`rust/qomm-demo`）の
API、WebSocket の内容、決済の意味は変えていません。動作の説明は
[../DEMO.md](../DEMO.md) を参照してください。

## 言い回しの決めごと

- 製品名（QOMM、DeFMI、zkPI、Maker、Taker、MP-SPDZ）はそのまま使い、役割は文で
  説明します。席の一覧は「注文を出す側（Taker）」「気配を出す側（Maker）」
  「計算ノード」の順に分け、それぞれ一行で何をする席かを添えます。
- 計算エンジンの札は「試作エンジン（比較は平文）」「秘密計算で価格照合」とし、
  実装名（Rust 試作、MP-SPDZ 実行）は説明文の側に残します。
- 段階の名前は動作で書きます。「注文と気配の方針を分けて配る」「入力が正しいか
  確かめる」「中身を見ずに価格を比べる」「注文者だけが読める結果を返す」
  「証明を確かめて DeFMI で決済」。復旧待ちには「（未成立）」を添えます。
- 「MPCノード」は「計算ノード」、「zkPI証明検証」は「決済の証明（zkPI）」、
  「DeFMI決済台帳」は「DeFMI 台帳」、「状態根」「台帳ハッシュ」は「台帳の識別値」。
- ラウンド番号の横の時間は経過時間なので「処理時間」と呼びます（以前の
  「完了まで」は残り時間に読めました）。
- 図の中の数値は実際の設定から出します。計算ノードの台数は部屋の設定、比較の
  方式はエンジン設定から表示し、固定文字（5 / 7、MP-SPDZ）は使いません。
- 英語表示も同じ方針で対応する語を更新しています（`?lang=en`、EN/JA ボタン）。

## 図の決めごと

- 図の幅は列幅に合わせて自動で縮小します（寸法や列幅が変わるたびに `fitView`）。
- 線の上の説明は文字幅の札にし、隣のカードにかかりません。
- 二列の指標の見出しは短くし（「予約分」）、銘柄名はツールチップに残します。

### 密度の修正（同日、親の指摘後）

- 値付けが 8 社ある机上表示では参加者カードが約 112px 幅になり、2 列の指標見出しが
  省略記号になっていた。カード幅が 140px 未満のときは「細幅カード」とし、指標を
  1 行ずつ「見出し＝値」で並べ、状態行を折り返し、高さを 196 に広げた。英語の見出しも
  短くし（cash / reserved / 銘柄名）、正式名はツールチップに残す。
  `audit/20260906/15-after2-observer-desktop.png`。DOM 検査で、8 枚の細幅カードに省略・
  折り返し・はみ出しがないことを確認。
- 狭い画面で図の上に大きな余白が出ていたのは、初回の `fitView` が高さ確定前の
  キャンバスで計算されたため。ノード計測後 300ms に再度 `fitView` を行う保険を入れた。
  再読込直後の実測で、図はキャンバス上端から 54px で始まる
  （`audit/20260906/16-after2-taker-narrow-390.png`）。
- 検査は build 9（描画・単体テスト 36 件、`serve_demo` ビルド）。`serve_demo.bin` の
  差し替えは試験サーバーを止めてから cargo ボリュームから取り出す手順に直した
  （稼働中は Text file busy になる）。

### 設計の説明と実装の保証の区別（同日、親の指摘後）

- 部屋のエンジンが試作（`engine: sim`）のときは、本文の目立つ位置（ヘッダー直下の帯）に
  「価格の比較は暗号化せず平文で行う」「席ごとの表示の絞り込みは画面上の投影で、秘密計算
  による保証ではない」と出す。秘密計算（MP-SPDZ）のときも、投影と保証の区別を一文で出す。
- 「分割された値だけが渡る」「どの計算ノードにも全体は渡らない」は「設計では」と付けて
  設計の説明として書き、試作エンジンではロビーの説明冒頭・計算ノード席・図の脚注に
  同じ注意を添える。工程名は「価格を比べる（試作：平文で比較）」、価格照合カードは
  「全社の気配を比較（平文）」に変わる。
- 台帳の記録先は断定しない。「設計では Avalanche 上の DeFMI に記録する」とし、実際の
  記録先は配信形態で分ける：ゲートウェイ無し（`serve_demo` 単体）は「プロセス内の試験用
  台帳で、DeFMI への記録ではない」、ゲートウェイ有りは「ゲートウェイ側の構成に従う」。
  判定はページに埋め込まれる `qomm-gateway-port` の有無による。
- 比較で選ばれた気配と実際の約定を分ける。決済状態が `settled` のときだけ「約定相手」
  「約定価格」と呼び、価格条件外で解放・復旧待ち・ダミーのときは「最良気配の候補（未約定）」
  「比較で選ばれた価格（未約定）」と表示する（価格照合カード、注文者の結果、全体表示の見出し）。
- 台帳カードの「決済」欄は状態で変える：同時引き渡し／確保分を解放／保留／変更なし／—。
